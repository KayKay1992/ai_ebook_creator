# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

AI eBook Creator: a full-stack app for generating, editing, and exporting eBooks. Users create a book, generate a chapter outline and chapter content via Gemini, edit chapters in a markdown editor, and export the finished book as PDF or DOCX.

Two independent apps, no shared code or monorepo tooling:
- `backend/` — Node/Express + MongoDB (Mongoose) REST API, CommonJS.
- `frontend/` — React 19 + Vite + Tailwind v4 SPA, ES modules.

## Commands

Run each app from its own directory (`backend/` or `frontend/`) — there is no root package.json.

**Backend** (`backend/`):
- `npm run dev` — start with nodemon (auto-reload)
- `npm start` — start with node
- `npm run backup` / `npm run restore -- <folder>` / `npm run backup:verify` — local database backup and restore, run on your PC only (see "Backups" under Cross-cutting notes).
- `npm test` — Jest + Supertest + mongodb-memory-server (`--runInBand`); no real MongoDB or third-party credentials needed, everything network-facing (Cloudinary, email) is mocked. No lint script configured.

**Frontend** (`frontend/`):
- `npm run dev` — start Vite dev server
- `npm run build` — production build
- `npm run lint` — ESLint (flat config, `eslint.config.js`)
- `npm run preview` — preview a production build
- `npm test` — Node's built-in test runner (`node --test "src/**/*.test.js"`) for the few pure, DOM-free modules (`utils/annotationAnchor.js`, `utils/speechText.js`, `utils/analyticsSeries.js`, `utils/kenlibsPricing.js`, `utils/errorNoise.js` + `utils/registerServiceWorker.js`, `utils/passkeyErrors.js` + `utils/passkeySupport.js`, `utils/rateLimit.js`, `utils/kenlibsTabBar.js`, `utils/library.js` + `utils/readingProgress.js`, `utils/theme.js` + `utils/themeStore.js`). No component tests, no extra dependency.

## Environment

The backend needs **Node 20 or newer** (`@simplewebauthn/server`; `backend/package.json` `engines`). `server.js` exits at startup with a clear message on older Node (`utils/nodeVersion.js`). On Render, set `NODE_VERSION` (e.g. `22`) if its default is older.

Backend expects a `.env` file in `backend/` (gitignored, see `backend/.env.example`) with at least: `PORT` (8000 in dev; Render sets this itself in production), `MONGO_URI`, `JWT_SECRET`, `GEMINI_API_KEY`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` (image uploads — see below), `BREVO_API_KEY` + `EMAIL_FROM` (password reset and purchase emails via Brevo's HTTPS API — required on Render, whose free tier blocks outbound SMTP), or `GMAIL_USER` + `GMAIL_APP_PASSWORD` as an SMTP fallback for local dev (`utils/sendEmail.js` picks Brevo when `BREVO_API_KEY` is set).

`ADMIN_NOTIFY_EMAIL` (optional, comma-separated) is who receives the admin purchase-request emails; unset means every `role: 'admin'` user.

Audiobook narration (all optional, see `backend/.env.example`): `TTS_MODEL` (default `gemini-3.8-flash-tts`), `AUDIO_DAILY_CHAR_LIMIT` (default 100,000 characters per UTC day), `AUDIO_URL_TTL_SECONDS` (signed audio URL lifetime, default 3600), `AUDIO_TTS_CONCURRENCY` (default 1), `AUDIO_TTS_MIN_INTERVAL_MS` (default 0), `AUDIO_PROVIDER` (`gemini` default, or `local` for a backend running on your own PC), `LOCAL_TTS_DTYPE` (`fp32` default, or `q8`). `node scripts/tts-sample.js` (from `backend/`) makes a ~20s sample MP3 to try voices/models; `--upload` also checks Cloudinary authenticated delivery.

Passkeys: `WEBAUTHN_ORIGIN` (default `FRONTEND_URL`), `WEBAUTHN_RP_ID` (default that origin's host, e.g. `kenlibs-sooty.vercel.app`), `WEBAUTHN_RP_NAME` (default `Kenlibs`). They describe the **frontend**, never the Render API. **Changing the RP ID (e.g. a custom domain) makes every existing passkey unusable**; passwords keep working and users add a new passkey.

Password brute-force limits (all optional, see `backend/.env.example`): `AUTH_LOGIN_WINDOW_MINUTES` (15), `AUTH_LOGIN_MAX_FAILS_PER_IP_EMAIL` (10), `AUTH_LOGIN_MAX_FAILS_PER_IP` (100), `AUTH_FORGOT_MAX_PER_IP` (20/h), `AUTH_FORGOT_MAX_PER_EMAIL` (5/h), `AUTH_REGISTER_MAX_PER_IP` (10/h), `AUTH_RESET_MAX_PER_IP` (20/h).

`FRONTEND_URL` (defaults to `http://localhost:5173` if unset) is the single canonical production frontend URL, used only for building links in emails (password reset links via `authController.js`'s `buildResetLink`, and the purchase emails' links) and the OG-preview crawler redirect (`routes/ogPreviewRoute.js`) — both contexts where "one real answer" is what's needed, not a set.

CORS is driven by a separate pair of vars (`app.js`), since it needs to allow more than one origin at once (production + Vercel preview deployments):
- `ALLOWED_ORIGINS` — comma-separated list of exact allowed origins. Falls back to `FRONTEND_URL` alone if unset, so local dev needs nothing extra.
- `ALLOWED_ORIGIN_PATTERN` — optional, opt-in only (unset = no wildcard matching at all). A single-`*`-wildcard host pattern (one `*` = one DNS label, anchored) for allowing e.g. `https://*.vercel.app` preview subdomains without hand-maintaining every preview URL in `ALLOWED_ORIGINS`. See `app.js`'s `ORIGIN_PATTERN` comment for exactly what it does and doesn't match, and `backend/tests/cors.test.js` for the behavior under test.

The frontend's API base URL is read from `import.meta.env.VITE_API_URL` in `frontend/src/utils/apiPaths.js` (`BASE_URL`), with a `http://localhost:8000` fallback for local dev only — it's **required** in every deployed environment (see `frontend/.env.example`).

## Architecture

### Backend (`backend/`)

Standard Express MVC-ish layering: `routes/` → `controller/` → `models/`, with `middleware/` for cross-cutting concerns. `app.js` builds the Express app and mounts every router (`/api/auth`, `/api/books`, `/api/ai`, `/api/export`, etc.) with zero side effects on require, so tests can import it directly with supertest; `server.js` is the only file that connects to Mongo and calls `app.listen`.

- **Auth**: JWT-based. `middleware/authMiddleware.js`'s `protect` reads a `Bearer` token, verifies it, and attaches `req.user` (password excluded). Every books/ai/export route is protected; ownership is enforced in each controller by comparing `book.userId` to `req.user._id`, not by middleware.
- **Data model** (`models/Book.js`): a `Book` embeds its `chapters` as a subdocument array (title/description/content) rather than a separate collection — chapters are always loaded/saved with their parent book. `previewContent` (max 2,000 chars) is the storefront teaser: the only long-form text written for the public book page, drafted via `/api/ai/generate-teaser` (metadata + chapter titles/descriptions only, never chapter content) or by hand, and always reviewed/saved by the admin. It's returned only by the single-book public endpoint, never the storefront listing. `coverDesign.back.blurb` is separate back-cover copy that is also public. `audio` holds per-chapter AI narration state (see Audiobook mode under Cross-cutting notes). `models/User.js` hashes passwords via a `pre('save')` hook and exposes `matchPassword`.
- **AI generation** (`controller/aiController.js`): uses `@google/genai` (Gemini, model `gemini-2.5-flash`) with large hand-tuned prompts to (1) generate a JSON chapter outline and (2) generate markdown content for a single chapter. Outline responses are parsed by locating the first `[` and last `]` in the raw text — the prompt format must keep producing a bare JSON array for this to keep working.
- **File uploads** (`middleware/uploadMiddleware.js`): Multer memory storage (image mimetypes only; 5MB limit for the cover, `coverImage` field; 8MB limit for chapter images, `chapterImage` field) — files are held in `req.file.buffer` and never written to local disk. Controllers (`bookController.js`'s `updateBookCover`/`uploadChapterImage`) pipe the buffer straight to Cloudinary via `utils/cloudinaryUpload.js`, uploading into `ebook-creator/covers/` or `ebook-creator/chapters/` respectively, and store the returned `secure_url` (an absolute URL) on the `Book` doc / in the inserted markdown image reference. There is no local `/uploads` static route — old pre-migration `backend/uploads/` files and any `/uploads/...`-prefixed paths still in the DB are no longer served.
- **Export** (`controller/exportController.js`): the largest/most intricate file. Two independent hand-rolled markdown-to-document renderers share the same `markdown-it` token stream but are otherwise separate implementations:
  - `exportAsDocument` walks markdown-it tokens into `docx` `Paragraph`/`TextRun` trees (headings, lists, blockquotes, code blocks, inline bold/italic) and streams a `.docx` via `Packer.toBuffer`.
  - `exportAsPDF` walks the same token stream directly into a `pdfkit` `PDFDocument` (manual cursor/`moveDown` layout), and separately strips markdown to plain text for the DOCX chapter body (note: DOCX chapter *body* text uses a simpler regex-strip approach, not the token walker, while headings/title page do use rich formatting).
  - Both embed the book's cover image, fetched over HTTP from its Cloudinary `coverImage` URL, if present and not a placeholder (`pravatar`) URL — a failed/unreachable fetch is logged and the image is skipped rather than crashing the export. EPUB export additionally downloads the cover and any chapter images to temp files (`os.tmpdir()`) since `nodepub`'s metadata API expects on-disk paths, cleaning them up after the EPUB is built.
  - When modifying markdown rendering, changes generally need to be made in both places to keep PDF/DOCX output consistent.

### Frontend (`frontend/src/`)

- **Routing** (`App.jsx`): `react-router-dom` v7, flat `Routes`. Public: `/`, `/login`, `/signup`. Protected (wrapped in `components/auth/ProtectedRoute.jsx`): `/dashboard`, `/profile`, `/editor/:bookId`, `/view-book/:bookId`. Reader pages (`ReaderRoute`) include `/kenlibs/profile` (account + passkeys).
- **Auth state** (`context/AuthContext.jsx`): custom context (`useAuth`), not a library — token/user persisted in `localStorage` (`token`, `user`), consulted synchronously at mount. `logout()` hard-redirects via `window.location.href`.
- **API layer** (`utils/apiPaths.js` + `utils/axiosInstance.js`): all endpoint paths centralized in `API_PATHS`; a single shared `axiosInstance` attaches the bearer token from `localStorage` on every request via an interceptor. Always add new endpoints to `API_PATHS` rather than inlining URL strings.
- **Editor** (`pages/EditorPage.jsx` + `components/editor/*`): the core workflow screen. Holds the whole `book` object (including all chapters) in local state, mutates it locally, and calls `PUT /api/books/:id` to persist. Field edits through `handleBookChange` autosave after a 2.5s debounce (`scheduleAutosave`). AI-drafted text the admin hasn't reviewed (the storefront teaser via `handleBookChange(e, { unreviewedDraft: true })`, chapter summaries via `handleSummaryDraft`) sets `isDraftPending`, which pauses **all** automatic saves of the book (debounced autosave and the post-AI-chapter save) until the manual Save button succeeds, so an unreviewed draft can't reach readers through some other field's autosave. Any new automatic save path must check `draftPendingRef` too. Cover upload and the publish toggle take only the fields they changed from the server's response (`applyServerFields`), never the whole book, so they can't revert pending drafts or unsaved edits. Chapter summaries (`chapter.summary`, max 1,200, enforced in `updateBook`; `summaryEdited`, `summarySourceHash`) are drafted one chapter at a time by `POST /api/ai/chapter-summary` (owner/admin, returns a draft and saves nothing, own 120/hour limit, retries via `utils/geminiRetry.js`, 429 with `quota: "daily" | "minute"`), edited in `components/editor/ChapterSummariesPanel.jsx` (Details tab; "Generate for all" skips chapters that have a summary; regenerating an admin-edited summary asks first), and shown as a collapsible "Chapter recap" only in the gated reader (`components/kenlibs/ChapterRecap.jsx`). `readBook` drops `summaryEdited`/`summarySourceHash`; the public share link never includes summaries (see Share link below). There's also an explicit "Save" button, and saves triggered right after AI content generation (`handleSaveChanges(updatedBook, false)`). Chapter reordering uses `@dnd-kit` (`arrayMove`). Chapter markdown editing uses `@uiw/react-md-editor` (`SimpleMDEditor.jsx`). Export buttons hit `/api/export/:id/pdf|doc` with `responseType: "blob"` and trigger a client-side download.
- **Styling**: Tailwind v4 via `@tailwindcss/vite` plugin (no `tailwind.config.js` — v4 uses CSS-based config in `index.css`). Icons via `lucide-react`. Toasts via `react-hot-toast`, mounted once in `main.jsx`.
- **Fonts** (self-hosted, no Google Fonts): `src/fonts.css` declares `@font-face` for files from the `@fontsource-variable/*` packages (Latin + Latin Extended only; Latin Extended carries ₦ and loads only when used), all `font-display: swap`. Inter = body (`font-display` token), Fraunces = serif titles (`font-serif`, weight + optical size), Fraunces Soft = the storefront hero headline only (`font-headline`, SOFT axis), Nunito = Kenlibs wordmark, hero sub-line and tab labels only (`font-rounded`). Only the hero's Fraunces Soft Latin file is preloaded (`index.html`; Vite rewrites the path to the hashed asset). `vite.config.js` keeps italic and Latin Extended font files out of the service worker precache.
- **Reader-facing brand** (from the flier, `design-ref/Gemini_Generated_Image_.jpg`): tokens `--color-forest` (#09262e, header bars), `--color-forest-deep`/`-deeper` (hero gradient), `--color-forest-leaf`/`-leaf-light`, `--color-accent-on-dark` (#ec894a, orange text on green). Green on every reader-facing page: `KenlibsNav`, `KenlibsFooter`, and `ViewBook` with `headerTheme="brand"` (gated reader and share preview; the admin preview keeps the default white header, admin keeps navy). `components/kenlibs/KenlibsLogo.jsx` is the logo (inline SVG). Small orange text on cream uses `accent-hover` (5.7:1), not `accent` (4.0:1).
- **Storefront home** (`pages/KenlibsPage.jsx`): full-width green hero (`KenlibsHeroLeaves.jsx` inline SVG leaves, no image), one `h1` "Discover Great Books on Kenlibs" rendered without entrance animation (so it paints for LCP), `KenlibsSearchBar` (white pill, labelled, client-side filter by title/author over the loaded books, shown immediately). Featured: phones (`useMediaQuery`, below 640px) get a two-per-row grid of the first 4 (`KenlibsBookCard fluid`); wider screens keep the fanned row. Rows use `scroll-pl-*` so snapping keeps their left padding.
- **Phone tab bar** (`components/kenlibs/KenlibsTabBar.jsx`, rules in `utils/kenlibsTabBar.js`, `npm test`): Home / Library (`/kenlibs/my-books`) / Profile (`/kenlibs/profile`), below `sm` only, on the storefront, book/bundle pages, Library, Referrals, Profile, Support and policies; never on the reader, share preview, checkout, login/signup/password pages or admin. `KenlibsThemeLayout` mounts it and, per the floating-controls rule, reserves its height + `env(safe-area-inset-bottom)` at the end of the page and lifts the WhatsApp button above it (`aboveTabBar`). Any new bottom-fixed element on these pages must account for the bar.

  - Preference `"system" | "light" | "dark"` (default System, follows `prefers-color-scheme` live) in localStorage `kenlibs_theme` (absent = System). ### Cross-cutting notes

- **Emails** (`utils/sendEmail.js`): `sendPasswordResetEmail`, `sendPurchaseRequestAdminEmail` (to the admin when a reader creates a purchase request, or resubmits a rejected one with `isResubmission: true`), and `sendPurchaseDecisionEmail` (to the reader on approve / reject / revoke, including the admin's note). All share `emailShell` and send HTML plus a plain-text version. Escape every user-supplied value (names, titles, notes) with the module's `escapeHtml` before it goes into HTML, and never put the payment evidence URL in an email. `purchaseController.js` sends them fire-and-forget: started only after the change has saved, never awaited before responding, failures caught and logged with the purchase request id. Awaiting an email in a request handler is what made forgot-password hang on Render, so don't. Tests: `tests/purchaseEmails.test.js` (other purchase suites stub the two helpers).
- **Audiobook mode** (AI narration; the browser-voice Listen Mode, `hooks/useListenMode.js`, stays the fallback for chapters without audio):
  - Pipeline: `utils/narrationText.js` (chapter markdown → plain narration text: drops code, images, URLs, HTML; keeps link text; title read first; ~1,800-char chunks split only between paragraphs/sentences) → a provider (below; returns 24 kHz 16-bit mono PCM) → `utils/audioEncoding.js` (64 kbps mono MP3 via `@breezystack/lamejs`, pure JS, loaded from its IIFE build because Jest can't `import()`; yields to the event loop while encoding) → `utils/audioStorage.js` (Cloudinary `resource_type: 'video'`, `type: 'authenticated'`; `utils/cloudinaryUpload.js` takes an `options` argument for this).
  - Providers (`utils/narrationProviders.js`, `AUDIO_PROVIDER=gemini|local`, default gemini): `gemini` = `utils/tts.js` (charges `AUDIO_DAILY_CHAR_LIMIT`; default concurrency 1, `AUDIO_TTS_MIN_INTERVAL_MS` spacing; parses the 429 body's QuotaFailure/RetryInfo: per-minute limits are waited out without using retries, a daily limit throws `QuotaExhaustedError` at once). `local` = `utils/localTts.js` + `utils/kokoroEngine.js`: Kokoro-82M (Apache-2.0) via kokoro-js, CPU, ~1x real time, ~900MB RAM, 28 English voices, default `af_heart`, fp32 (`LOCAL_TTS_DTYPE=q8` optional). kokoro-js is **not** a backend dependency: it lives in `scripts/local-tts/` with its own package.json (`npm install --prefix scripts/local-tts`) so ~400MB of ONNX runtime never ships to Render; the model caches in `scripts/local-tts/.model-cache/` (gitignored). Tests mock `utils/kokoroEngine.js`.
  - Shared narration (`utils/narrationPipeline.js`'s `narrateClaimedChapter`), used by both the server worker and `scripts/narrate-book.js`, so both write identical `book.audio` fields (status, source `gemini|local|uploaded`, duration, bytes, textHash, voice). Chunk-level resume: each finished chunk is encoded and uploaded at once as its own authenticated "part" (`entry.parts`, `ebook-creator/audio/<bookId>/parts`, keyed by hash of engine+voice+gap+text); a retry reuses matching parts and makes only the missing ones (`chunksDone`/`chunksTotal`), then the parts' MP3 bytes are concatenated into the chapter file and the parts deleted. Daily Gemini quota → that chapter and every queued one become `waiting` ("Daily Gemini limit reached…"), not failed. `heartbeatAt` is refreshed while generating; a `generating` entry with a stale heartbeat (>3 min) counts as interrupted (shown failed, can be regenerated, deleted, or taken over by `claimChapter`).
  - Jobs (`utils/audioJobs.js`): the DB is the queue (`audio.chapters[].status: 'queued'`); one in-process worker, one chapter at a time. HTTP handlers only queue and `kick()`. `server.js` calls `recoverInterruptedJobs()` after Mongo connects (generating with a stale heartbeat → failed, parts kept; a live `narrate-book.js` run is left alone; queued resumes). Write audio state only with targeted per-entry updates (`$elemMatch`/`arrayFilters`), never `book.save()`, since the worker and the script update entries concurrently. `updateBook` strips `audio` from the body and `getBookById`/`getBooks` exclude it, so editor saves can't overwrite job state.
  - Local narration script: `node scripts/narrate-book.js` (from `backend/`, uses `backend/.env`'s `MONGO_URI` + `CLOUDINARY_*`) lists books; `<bookId>` narrates chapters missing audio or out of date; `--chapter N|id`, `--voice`, `--skip-existing`, `--force`, `--dry-run`, `--list-voices`, `--provider gemini`. Resumable at chapter and chunk level; Ctrl+C once stops after the current part. All console output is passed through a redactor so secrets/URL credentials never print. `scripts/local-tts-sample.js` makes a ~30s sample.
  - Admin endpoints (`controller/audioController.js`, under `/api/books/:id/audio`, owner-checked): `GET` status (incl. `isStale` from `textHash`, `provider`, `source`, `chunksDone`/`chunksTotal`), `POST /generate` (`{ chapterId | "all-missing", voice, dryRun }`; dry run returns chars/estimate/daily budget, the real call returns 202 and reserves against `AUDIO_DAILY_CHAR_LIMIT` for Gemini only), `POST /preview` (first sentence only, returns `audio/mpeg`), `DELETE /:chapterId` (also deletes saved parts), `POST /:chapterId/upload` (multipart field `audio`, `.mp3` only, 50MB, frames validated and duration measured by `utils/mp3Info.js`, ≤4h; stored authenticated like generated audio, `source: 'uploaded'`; replaces old audio/parts; 409 while generating). Characters are charged when a chapter starts (`utils/audioUsage.js`, `AudioUsage` model). Audio for deleted chapters is never auto-deleted (listed as orphaned in the editor); book deletion deletes all its audio files and parts.
  - **Never expose `publicId` or audio URLs publicly.** Public endpoints only get `hasAudio`/`audioChapterCount` (`utils/audioSummary.js`); `GET /api/kenlibs/audio/:bookId` (`hasBookAccess`, like `readBook`) is the only source of signed, expiring `private_download_url`s (verified: served by api.cloudinary.com without redirect, supports Range/seeking, 401 after expiry; not CDN-cached, double bandwidth).
  - Frontend: editor "Audiobook" tab (`components/editor/AudiobookTab.jsx`, lazy) talks only to its own endpoints and polls while working. `EditorPage.jsx`'s `adoptServerChapterIds` copies server-assigned chapter `_id`s into newly added chapters after a save, so audio keyed by chapter id doesn't detach. Reader: `components/kenlibs/AudiobookPlayer.jsx` (lazy, only when the book has audio): ±15s, 0.75–2x, seek, chapter list, auto-advance, Media Session, refreshes expired URLs and resumes; positions/speed in localStorage per book and chapter id. `vite.config.js` keeps audio out of the precache and runtime caches. The tab also has a per-chapter "Upload audio" button, "Continue" for runs with saved parts, a "Waiting for quota" state, and a note with the exact `narrate-book.js` command for the book. Tests: `tests/narrationText.test.js`, `tests/audiobook.test.js`, `tests/audioProviders.test.js` (providers, resume, quota, upload, heartbeat, MP3 parsing).
- **Reader highlights, notes and bookmarks** (gated reader only, private per reader):
  - Storage: `models/ReaderAnnotation.js`, one doc per highlight/bookmark (`reader`, `book`, `chapterId`, `language` = `'original'` or a translation code, `type` `highlight|bookmark`, `color` yellow/green/blue/pink, `note` ≤1,000, `label` ≤120, `anchor`). Endpoints in `controller/annotationController.js` under `/api/kenlibs/annotations/:bookId` (`GET`, `POST`, `PUT|DELETE /:annotationId`): every one checks `hasBookAccess` (exported from `kenlibsController.js`; 403 without access) and filters every query on `reader: req.user._id` (someone else's id is a 404). Writes rate-limited (300 / 15 min / user), `READER_ANNOTATIONS_MAX_PER_BOOK` (default 2,000, 409 `code: "limit"`), notes/labels cleaned to plain text (rendered by React as text, never HTML). Never on any public or admin endpoint; deleted with the book (`deleteBook`) and with the reader's account (`deleteUser`, both the hard-delete and the anonymise path). Tests: `tests/annotations.test.js`.
  - Anchoring (`frontend/src/utils/annotationAnchor.js`, pure, `npm test`): `{ paragraphIndex, startOffset, endOffset, quote, prefix, suffix }`. `paragraphIndex` is the Listen Mode block index (`data-paragraph-index` on each `listen-block`), offsets are into that paragraph's rendered `textContent`. `resolveAnchor` tries the offsets, then the quote anywhere in the chapter disambiguated by prefix/suffix (ties prefer the original paragraph), else `changed`: kept and shown in the panel as "Text changed", never deleted. Single-paragraph highlights only (a cross-paragraph selection is clipped to the first, with a toast). - **Backups (local, on your PC; nothing runs on Render).** From `backend/`, using `.env`'s `MONGO_URI`:
  - **Back up:** `npm run backup` writes `backups/<YYYY-MM-DD_HHmm>/` with every collection the database has (listed from the database, not the models) as `<collection>.json` (a JSON array, one Extended JSON document per line, so ObjectIds/Dates restore exactly; streamed in batches), plus `manifest.json` (date, source host + database name, per-collection document count, sha256, index definitions). `--out <dir>` for another location, `--keep N` to delete all but the newest N backups there (only folders named like a backup that contain a manifest; off by default).
  - **Check a backup:** `npm run backup:verify [-- <folder>]` (newest by default) verifies checksums/counts, restores into a new temporary database `kenlibs_verify_<timestamp>` on the same server, compares counts, then drops it. The real database is never written.
  - **Restore:** `npm run restore -- <folder>` is a **dry run** unless `--apply`; it verifies every checksum and count first and stops on any mismatch. It refuses to write into the database the backup came from unless `--yes-overwrite` is given **and** you type the database name at the prompt (interactive terminals only). Use `--target-uri "<uri>"` and/or `--target-db <name>` to restore elsewhere, `--only a,b` for some collections. Without `--drop` it never drops anything: it adds documents and skips `_id`s that already exist (never overwrites); with `--drop` the target collections are replaced. Indexes are recreated from the manifest.
  - **Code:** logic in `backend/utils/backup.js`, CLIs in `backend/scripts/backup.js`, `restore.js`, `backup-verify.js` (shared `scripts/lib/cli.js`: loads `backend/.env` by absolute path, masks credentials and query strings in every printed line). Tests: `tests/backup.test.js`.
  - **Privacy:** backups contain **personal data**: emails, bcrypt password hashes, reset tokens, purchases and payment evidence URLs, the admin's bank/payment details (`users.paymentDetails`), readers' private notes and highlights. Keep them private; never commit, upload or share them. `backups/` is git-ignored and every backup folder has its own `.gitignore` of `*`.
  - **Not included:** images and audio are in Cloudinary; a backup only holds their URLs/ids, so restoring data doesn't restore those files (and deleting them from Cloudinary breaks restored references).
  - The real database is named `test` (the URI has no database name).
